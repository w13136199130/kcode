# M0 实施与验收记录

更新：2026-09-24。范围依据 [优化路线图](optimization-roadmap.md) 的 M0-01～M0-06。

## 当前结论

M0 的代码与自动回归已落实，真实终端人工体验验收仍待完成。当前定位是输入和运行控制更可靠的开发版；会话恢复、压缩与回退一致性属于 M1，不能据此宣称可靠 Beta。

| 项目 | 实现与证据 | 状态 |
| --- | --- | --- |
| M0-01 失败基线 | Hook、Git Bash、DPAPI 分别定位；真实子进程与加密落盘回归 | 自动验证通过，跨平台验证待补 |
| M0-02 提交门禁 | gate 先于有效历史、技能注入；拒绝返回 rejected；下一次请求不含被拒绝文本或技能正文 | 自动验证通过 |
| M0-03 输入保真 | 移除拼音猜测和中文后吞数字；稳定输入订阅读取最新处理器；LF/CRLF 多行粘贴不误提交 | 自动验证通过，真实 IME 待验收 |
| M0-04 Unicode | 字符簇移动/删除、终端显示宽度与截断；区分 DEL 退格和 Delete；组合重音及家庭 emoji、80/120 列回归 | 自动验证通过，终端字形待验收 |

## 本轮补齐的边界

- 客户端先注册结束通知再发送，避免快速拒绝或空响应先完成、界面却一直 busy。旧 run 的完成通知不结束当前 run。
- 审批使用独立随机 ID，避免两个会话复用模型 callId 时覆盖等待项。取消仅结算目标会话；取消后异步生成的预览不再弹出。
- 工具执行前再次检查取消，覆盖等待权限、用户批准和 pre_tool_use Hook 的阶段。
- 输入处理器使用稳定订阅，避免上一帧闭包覆盖紧接中文输入的数字。DEL 在 Ink 解析前归一为退格，Delete 保持向前删除。
- Hook 超时结束进程树并明确报告超时。测试脚本真实保持事件循环运行，不再把自行退出误当超时；Windows 多进程测试外层允许 15 秒，真实 Hook 超时仍为 800ms。
- Git Bash 子进程补入所选安装的工具目录，解决 PATH 只有 Git/cmd 时 sleep、cygpath 不可用，以及会话 cd 后路径换算失败。
- PowerShell DPAPI 显式使用 UTF-8 与终止错误处理；测试使用新实例重新从磁盘解密，覆盖中文和 emoji，避免只读取 set() 的明文缓存。

## 原失败分类与复现

| 分类 | 复现入口 | 根因与处理 |
| --- | --- | --- |
| Hook 提交拒绝 | `pnpm test packages/core/test/hooks-gates.test.ts` | 输入先进入历史再被否决，后续请求可能泄漏；提前 gate，并验证后续正常轮次 |
| shell 超时、cd | `pnpm test packages/tools/test/bash.test.ts` | 非 login Git Bash 没有自己的工具 PATH；补入所选安装路径 |
| Windows DPAPI | `pnpm test packages/platform/test/dpapi-keychain.test.ts` | 受限环境无法使用 CurrentUser 配置；正常 Windows 用户环境实跑通过，另修复 UTF-8 与失败传播；未跳过 Windows 测试 |
| Hook 回归基线 | `pnpm test packages/extensions/test/hooks.test.ts` | 原超时脚本自行退出；替换真实挂起脚本，补进程树清理及超时告警。Windows 全量负载下多次启动超出默认 5 秒，调整测试外层预算 |

DPAPI 的非 Windows 分支原本就不执行 Windows API；此结果不能代表 macOS/Linux 凭证后端通过。Windows 测试须运行在有可用用户配置文件的正常账户环境中。

## 模块职责与兼容性

| 模块 | M0 职责 |
| --- | --- |
| contracts | 终态、runId、协议消息定义 |
| runtime/session/runner | 同会话运行互斥、取消信号、运行结束后解锁 |
| core | gate、有效历史、模型循环终态、工具执行前取消检查 |
| daemon | 组装 runner、请求关联、审批隔离及取消路由 |
| cli | 先订阅后发送、按 runId 接收完成、输入与状态展示 |
| extensions / tools / platform | 分别处理 Hook 进程、shell 环境、系统凭证 |

本地协议版本为 10，客户端与 daemon 必须一起更新；开发时重启旧 daemon。M0 互斥与 runId 针对模型运行入口，尚未统一所有管理操作及用户直执行 `!` 命令的生命周期。

## 剩余人工验收（M0 优先）

入口、竞品官方行为对照及当前缺口见 [终端交互对照与验收](terminal-ux-acceptance.md)。2026-09-24 已通过离线入口连通性检查，真实输入法/字体验收仍未执行。

1. Windows Terminal + PowerShell、VS Code 集成终端分别输入“版本2”“修复3处”“api你好1”，切换输入法和选择候选，确认无误删、吞键或额外拼音。
2. 在 80/120 列窗口输入 `Aé👨‍👩‍👧‍👦中`，测试左右移动、Backspace、Delete、Home/End、历史回填；缩放窗口后不出现残留半字符。字形宽度仍受实际字体与终端影响。
3. 粘贴 LF/CRLF 多行代码，观察不会提前发送，再按 Enter 提交。分片粘贴和终端 bracketed-paste 协议仍需单独验收，当前自动覆盖单输入块。
4. 模型流式输出、执行 shell 时按 Esc，立即显示取消反馈，结束后才能重发。审批中的 Esc 按当前设计表示拒绝动作，整轮可以继续；整轮取消应有独立明确入口，当前 Ctrl+C 被菜单屏蔽的缺口需修复。区分工具拒绝、提交被拒绝、模型失败与轮次上限。

## 下一步：M1 的实施优先级

人工验收记录完成后，优先执行 M1-01～M1-03：**统一在线历史与持久化事件回放，确保压缩、回退后重启得到同一份有效上下文**。

先落以下回归场景，再改事件和归约器：

| 顺序 | 场景 | 验收标准 |
| --- | --- | --- |
| 1 | 自动压缩后继续两轮，再重启恢复 | 恢复历史与在线历史一致，摘要不会与被摘要的原文重复 |
| 2 | `/compact` 后立即关闭并恢复 | 压缩结果可回放，摘要与保留轮次准确 |
| 3 | 回退到较早提问后立即重启 | 已回退内容不复活；后续工具调用与结果成组完整 |
| 4 | 8～10 条短历史含多个并行工具调用 | 压缩不拆调用/结果组，无孤立 tool result |
| 5 | JSONL 尾行截断、写入失败、执行中崩溃 | 恢复有效前缀；不自动重放结果未知的写入操作 |

随后推进检查点持久化和 workspace/session 绑定，再做连接外的 SessionManager、attach 与事件游标。M1 验收后可达到有明确恢复语义的单机 Agent；字体主题、输出折叠和思考摘要层级主要在 M3 完善。
