# 终端交互对照与 M0 体验验收

日期：2026-09-24。对照对象是 Codex CLI、Claude Code CLI、OpenCode TUI；不将桌面应用的字体、布局直接套用到终端。

## 1. 官方行为与 kcode 的选择

本次核对的是官方文档，未在本机运行三款竞品，也不能据文档证明其所有中文输入法组合均正确。

| 维度 | 官方行为 | kcode 采用方向 |
| --- | --- | --- |
| Codex CLI | 支持代码块/diff 主题预览与配置；长提示可由 Ctrl+G 转外部编辑器 | 学习代码/diff 可读性及长输入逃生入口；外部编辑器列为后续功能。[官方定制说明](https://learn.chatgpt.com/docs/cli-customization) |
| Claude Code 输入 | Enter 发送；Ctrl+J、反斜杠续行为通用入口；Shift+Enter 取决于终端能力或配置 | 保留可靠换行键，单独验收 Shift+Enter，不把收到普通 Enter 猜成换行。[终端配置](https://code.claude.com/docs/en/terminal-config) |
| Claude Code 取消 | 运行中 Esc 中断；审批中 Esc 拒绝单次动作；Ctrl+O 查看详细记录 | Esc 按上下文路由；区分“拒绝工具”与“取消整轮”。工具摘要与展开保持层次。[交互说明](https://code.claude.com/docs/en/interactive-mode) |
| OpenCode 输入 | 将发送、换行、移动、删除和中断等动作独立配置 | 提取动作映射，避免输入框、菜单各自解释同一键值。[快捷键](https://opencode.ai/docs/keybinds/) |
| OpenCode 主题 | 有适配终端的 system 主题；提供自定义主题和真彩色能力说明 | 后续建立默认/弱化/成功/警告/失败色彩语义，支持终端默认色。[主题说明](https://opencode.ai/docs/themes/) |

字体由宿主配置：Windows Terminal 的 profile 提供 font face、size、weight 等参数；代码中的 ANSI 样式不能等同于任意 CSS 字体设置。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-appearance)

建议先用终端现有等宽字体验收，记录实际字体与字号；不同产品必须在相同宿主和字体下比较。中文和 emoji 的回退字形、亮暗主题、粗体/斜体效果需看真实屏幕，不能从测试字符串宽度推断。

## 2. 按优先级处理的具体差距

以下是本地代码审阅与官方行为对照后的结论，不冒充真实终端实测结果。

| 优先级 | 项目 | 当前证据 / 动作 |
| --- | --- | --- |
| P0 | 审批中取消整轮 | App.tsx 的 Ctrl+C 分支要求 `!menuOccupied`，审批出现时不起作用；Esc 当前仅拒绝。保留 Esc 拒绝，补明确的整轮取消动作及提示 |
| P0 | 真实 IME 保真 | 已有字符簇与中文数字自动回归；仍须实际选择候选、取消组合、混输、快速连续输入，不能用粘贴中文替代 |
| P0 | 粘贴边界 | 单块 LF/CRLF 已通过；补真实多块粘贴、bracketed paste 及尾部换行，验证不提前提交 |
| P0 | 真实状态文案 | 当前 spinner 随机取“检索中”等词，未必发生检索。改为事件驱动的等待模型/执行工具/等待确认/正在取消，耗时另列 |
| P1 | 光标与多行编辑 | 输入框当前用字符 `█` 表示光标；需检查它是否造成末列额外换行，以及 IME 候选窗是否跟随真实光标。多行上下移动与历史选择需分开 |
| P1 | 输入动作归一化 | 将字符簇编辑、按键解码、粘贴状态和菜单路由分层；Home/End 不依赖散落的全局 stdin 补丁。保留 React/Ink，先通过回归再评估更换渲染框架 |
| P1 | 输出与思考分层 | 正文常显；工具默认摘要，错误可见；模型提供的 reasoning 单独折叠和标明来源。模型推理强度与显示开关分开，不把 spinner 当作思考内容 |
| P1 | 字体与配色适配 | 当前多处硬编码 white、dimColor 和 emoji；浅色主题、低对比度、缺字形需验收。先补主题语义层，再增加风格预设 |
| P2 | 外部编辑器、可配置快捷键 | 借鉴 Codex 长提示外部编辑与 OpenCode 动作映射；放在输入基础稳定之后 |

M0 优先保证内容正确和可取消；主题系统、详情面板等按原路线图在 M3 完善，不因此延后 M1 恢复一致性。

## 3. 已准备的真实终端入口

从项目根目录运行：

```powershell
node apps/cli/node_modules/tsx/dist/cli.mjs apps/cli/scripts/m0-terminal.tsx
```

入口使用实际 KcodeApp、daemon、权限与工具管线，模型替换为确定性本地实现。每次创建独立工作目录、daemon 通道及输入历史，结果写入 `.artifacts/m0-terminal/run-*/observations.jsonl`。无需 API key；模型不调用网络。普通输入原样回显，可核对传给模型的文本。此入口验证指定场景，不替代生产启动、账号配置和真实 provider 验收。

| 输入 | 操作与预期 |
| --- | --- |
| `版本2`、`修复3处`、`api你好1` | 实际使用输入法键入并选候选；发送后回显与草稿一致 |
| `Aé👨‍👩‍👧‍👦中` | 左右移动、退格、Delete、Home/End，再发送；不拆组合字符 |
| `m0:font` | 查看中英文、易混字符、emoji、表格、代码高亮；分别在亮暗背景、80/120 列检查 |
| 任意多行文本 | 粘贴后停留在草稿；明确发送后，JSON 回显中的 `\n` 与原文相符 |
| `m0:stream` | 输出约 30 秒；按 Esc，中断反馈及时，保留已输出文本，终态 aborted，随后可发送新输入 |
| `m0:ask` | 出现写文件审批。Esc 表示拒绝该动作，模型可以继续总结；“拒绝工具”不等于 run rejected。整轮取消入口见上方 P0 缺口 |
| `m0:shell` | 选择仅本次允许；执行的是打印提示并等待 30 秒的本地命令。执行开始后 Esc 取消，检查能否再次输入 |
| `m0:error` | 显示人为构造的失败，终态 failed，不显示成功 |
| `m0:limit` | 重复只读 sample.txt，达到轮次上限，终态 limit_reached |
| `exit` | 空闲时退出，控制台打印记录路径 |

只使用表中验收命令即可。审批选择仅本次允许，避免会话放行导致下一次看不到审批菜单。
